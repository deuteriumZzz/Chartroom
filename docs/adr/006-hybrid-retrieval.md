# ADR-006: Гибридный поиск и граница qa ↔ knowledge

**Статус:** принято.

## Поиск
- **Два прохода в одном запросе Qdrant.** Dense-проход (cosine по эмбеддингу вопроса, `task_type=RETRIEVAL_QUERY`) и BM25-проход (термины вопроса с весом 1, IDF считает Qdrant) дают по 20 кандидатов. Результаты сливаются через **RRF** (Reciprocal Rank Fusion), наружу уходит top-k (по умолчанию 5, максимум 20).
- **Почему RRF.** Шкалы cosine и BM25 несравнимы, и взвешенная сумма потребовала бы калибровки весов. RRF складывает ранги, поэтому калибровки не нужно. Dense находит перефразировки («что делать при возгорании»), BM25 — точные термины и коды («SMS-F-12», «CO2», «MRCC»).
- **Только активные версии.** Оба прохода фильтруются по `version_id` активных версий; их список даёт Postgres (ADR-005). Пока ничего не проиндексировано, поиск сразу возвращает пусто, без вызова Gemini.
- **Вопрос без единого слова** (например, «?!») ищется только dense-проходом.
- **Реранкера пока нет.** Решение о cross-encoder — по метрикам eval (день 9).

## Граница модулей
- **Поиск принадлежит `knowledge`.** Модуль владеет индексом и знает активные версии.
- **`qa` дотягивается до поиска через свой порт** `PassageRetriever`. Его реализация — адаптер `qa/adapters/knowledge.py`, который переводит фрагменты `knowledge` в `Passage` модуля `qa` (anti-corruption layer). Это единственная связь `qa → knowledge`, и она явно разрешена в контракте независимости. Ядро `qa`, импортирующее `knowledge`, ломает сборку.
- **Порты эмбеддингов разделены** (ISP): API зависит только от `QueryEmbedder`, worker — от `Embedder` документов. Gemini-адаптер реализует оба.
- **Без `GEMINI_API_KEY` API всё равно стартует.** Вместо Gemini подставляется `UnconfiguredQueryEmbedder`: загрузка работает, а `/ask` при наличии документов отвечает 503.

## Следствие для политики отказа (день 6)
Оценка RRF показывает только позиции в выдаче, а не то, насколько фрагмент близок к вопросу: лучший результат на вопрос «не о том» получит примерно ту же оценку, что и на точный вопрос. Поэтому порог отказа по оценке RRF ставить нельзя. Нужен отдельный сигнал — сходство dense-прохода, оценка реранкера или проверка моделью, — а сам порог подбирается на eval.
