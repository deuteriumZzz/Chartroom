# ADR-001: Модульный монолит, порты и адаптеры внутри модулей

**Статус:** принято.

## Контекст
Система будет расти: RAG по процедурам, отчёты, агент с вызовом функций, оценка качества. Нужно, чтобы бизнес-логика не смешивалась с HTTP и БД, тестировалась без инфраструктуры, а внешние сервисы (LLM, векторное хранилище) заменялись без переписывания логики.

## Решение
- **Один деплой**: FastAPI и Celery-worker из одного кода.
- **Модули по предметным областям**: `identity`, `knowledge`, `qa`, `reports`, `agent`, `evaluation`.
- **Внутри модуля четыре слоя в плоских файлах**: `domain.py` → `ports.py` → `service.py`; по краям `api.py` (HTTP) и `adapters/` (БД, внешние сервисы).
- **Зависимости только внутрь.** Сервис знает порты (`typing.Protocol`), а не реализации. Порты связываются с адаптерами в одном месте — `bootstrap.py`.
- **Правила проверяет машина**: контракты import-linter в `pyproject.toml`, `make lint` и CI. Если `api.py` импортирует адаптер хранилища, сборка падает.

## Чего сознательно нет
- **Входящих портов** (интерфейса над сервисом): у сервиса одна реализация, такой интерфейс был бы мёртвым кодом. HTTP и CLI вызывают сервис напрямую.
- **DI-фреймворка**: контейнер — dataclass, вся сборка видна в одном файле.
- **Микросервисов**: у модуля уже есть граница и порты, вынести его в сервис можно, когда это понадобится.

## Последствия
- (+) Сценарии тестируются на фейках за миллисекунды. Совпадение поведения фейков с реальными адаптерами проверяют контрактные тесты.
- (+) Новый LLM-провайдер — это новый адаптер, сервисы не меняются.
- (−) Файлов больше, чем в схеме «роутер сам ходит в ORM». Это плата за заменяемость и тестируемость каждого слоя.
