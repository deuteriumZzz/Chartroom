# ADR-005: Конвейер индексации

**Статус:** принято.

## Поток
`POST /documents` → проверки (размер, сигнатура, название, версия, дубликаты) → версия `pending` в Postgres → задача в Redis → worker: `indexing` → разбор и нарезка → эмбеддинги → Qdrant → фрагменты в Postgres → `indexed` (или `failed` с причиной).

## Решения
- **Какая версия активна, знает только Postgres.** Активна версия с самой поздней датой выпуска; частичный уникальный индекс гарантирует, что такая версия одна. В Qdrant лежат точки всех версий (старая не теряется), а поиск фильтрует их по `version_id` активных версий. Флаг «активна» не дублируется в двух хранилищах, поэтому им нечему рассинхронизироваться.
- **Идемпотентность.** Id точки — `uuid5(version, chunk)`, фрагменты версии в Postgres перезаписываются целиком. Повтор задачи (ретрай или двойная доставка) ничего не дублирует.
- **В очередь — после commit.** Иначе worker может получить id ещё не сохранённой версии.
- **Ошибки.** Бизнес-ошибка (битый файл, нет текста) — сразу `failed`, без повторов. Недоступный провайдер или хранилище — `failed` и повтор с экспоненциальной паузой (до 3 раз); при успехе статус восстанавливается. Любая непредвиденная ошибка тоже ставит `failed`, поэтому версия не может навсегда остаться в `indexing`.
- **Worker.** `acks_late` — задача подтверждается после выполнения, и падение worker-а её не теряет. Мягкий лимит 120 с: по истечении версия получает `failed`, «Indexing timed out». Каждая задача запускает свой event loop, поэтому движок БД в worker работает без пула соединений. Без `GEMINI_API_KEY` worker не стартует: проверка выполняется при импорте модуля, потому что Celery глотает исключения в обработчиках сигналов (см. `docs/ai-log.md`).
- **Эмбеддинги.** `gemini-embedding-001`, 768 измерений, `task_type=RETRIEVAL_DOCUMENT`, метрика cosine. Перед текстом фрагмента ставятся название документа и путь раздела: короткий фрагмент без контекста ищется хуже. Лимит текстов на запрос не документирован, поэтому пачка — 100.
- **Sparse (BM25).** Клиент считает только частоту термина с насыщением (k1 = 1.2, b = 0.75, средняя длина 40 слов), IDF Qdrant считает по всей коллекции (`modifier=IDF`). Стемминга нет: эффект на русской морфологии проверит eval (день 8–9).
- **Файл хранится в Postgres** (`bytea`, отложенная загрузка) рядом с версией: так проще и сохраняется транзакционность. Для продакшена — S3/MinIO со ссылкой в версии.

## Известные ограничения
- **Нет outbox.** Если брокер упал после commit, клиент получает 503, а версия остаётся `pending`. Исправление — transactional outbox или периодическая повторная постановка «зависших» `pending`.
- **Лимит 20 МБ проверяется после приёма тела.** Starlette к этому моменту уже принял файл целиком. В продакшене тело должен ограничивать reverse proxy (например, `client_max_body_size` в nginx).
