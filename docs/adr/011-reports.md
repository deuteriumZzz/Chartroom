# ADR-011: Отчёты и чек-листы (M2)

**Статус:** принято.

## Шаблон — JSON Schema из явного подмножества
- **Что поддерживается.** Типы `string`, `number`, `integer`, `boolean`; `minimum`/`maximum`, `enum`, `format: date|time`, `required`. Для согласованности полей — одно расширение: `x-lte`, «поле A не больше поля B». Например, «присутствовало ≤ экипаж по роли» или «первый конец ≤ ошвартованы».
- **Строгость.** Шаблон с любым другим ключом (`pattern`, `oneOf`, вложенные объекты) отклоняется при создании. Наполовину применённая схема, где часть правил молча игнорируется, опаснее явной ошибки.
- **Свой валидатор (~60 строк) вместо библиотеки `jsonschema`.** Это ядро M2: его логику автор объясняет построчно, а сообщения нужны в своём формате (`field` + `message`). Библиотека добавила бы зависимость ради шести ключевых слов и перевод её ошибок в наши.
- **Версии.** Новый шаблон с тем же именем — новая версия, а отчёт ссылается на конкретную. Одновременное сохранение одной версии даёт 409 (проверено тестом с двумя настоящими транзакциями).

## Извлечение
- **Как устроено.** Gemini получает схему и текст и возвращает JSON. Промпт `reports/prompts/extract.v1.md`: не указанное — `null`, ничего не вычислять и не додумывать.
- **Модели не доверяем.** Любой её ответ проходит `validate()`: неизвестные поля, неверные типы и пропуски становятся замечаниями, а не данными.
- **Prompt injection.** Текст отчёта передаётся экранированным в теге `<report>`.
- **Надёжность.** Та же цепочка моделей, что у ответов (общий `shared/gemini.py`, ADR-007).

## Статусы
- **`needs_review`** — есть замечания; **`draft`** — замечаний нет.
- **Правка (PATCH)** накладывает исправленные поля поверх извлечённых и пересчитывает замечания: исправленное поле перестаёт быть замечанием.
- **`accepted`** ставит только captain или admin и только без замечаний; после этого отчёт не меняется.
- **Доступ.** Officer видит и правит свои отчёты, captain и admin — все. Чужой отчёт отвечает 404 (IDOR), как журнал запросов (ADR-008).

## Отклонения от первоначального плана
- **Таблицы `report_issues` нет:** замечания лежат одним JSONB-полем в `reports`. Они всегда пересчитываются целиком, и отдельная таблица дала бы только лишние удаления и вставки при каждой правке.
- **Стартовые шаблоны** (суточный отчёт, учебная тревога, швартовка) лежат в `data/templates/`, их засевает `make seed`.
