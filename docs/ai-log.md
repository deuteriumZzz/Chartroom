# Журнал ошибок ИИ

Проект пишется вместе с ИИ-ассистентом. Здесь честно записано, где он ошибся, как ошибку поймали и что изменилось в процессе. Каждая запись — это проверка или правило, которых раньше не было.

---

### 2026-11-11 · Ложный «зелёный» `/health`
- **Что произошло.** После `docker compose up` запрос на `localhost:8080/health` вернул `{"status":"ok"}`, и ассистент был готов засчитать проверку. Отвечал чужой контейнер с того же порта: compose-файл с новым портом не сохранился, Chartroom слушал другой порт.
- **Как поймали.** Сверили `docker compose ps` с портами и логами контейнера: запроса в логах Chartroom не было.
- **Что изменили.** Порт API настраивается (`API_PORT`, по умолчанию 8088). Проверка считается пройденной, только если запрос виден в логах нашего контейнера.

### 2026-11-11 · «Healthy» до того, как API готов
- **Что произошло.** `docker compose up --wait` отчитался `api Healthy`, но первый запрос к `/health` вернул пустой ответ: миграции и uvicorn ещё стартовали. У сервиса не было healthcheck, и compose считал готовым любой запущенный контейнер.
- **Как поймали.** Финальная проверка с нуля: пустой ответ не засчитали, а сверили с логами контейнера.
- **Что изменили.** Healthcheck у `api` проверяет `/health` изнутри контейнера, теперь `--wait` означает «API отвечает».

### 2026-11-11 · Два дня работы одним коммитом
- **Что произошло.** Дни 1–2 ушли в один коммит на 43 файла: историю не прочитать, правку не откатить по отдельности.
- **Как поймали.** Автор сверил проект с отзывом ревьюера на прошлое тестовое, где именно это было минусом.
- **Что изменили.** История пересобрана: одна логическая правка — один коммит, каждый проходит линтеры и тесты. Правило записано в ТЗ.

### 2026-11-11 · Хендлер ходил в БД напрямую
- **Что произошло.** В первой версии ADR-002 ассистент отказался от слоя репозиториев («SQLAlchemy и так Unit of Work»). В итоге зависимость `get_current_user` в API-слое сама делала `session.get(User, ...)`.
- **Как поймали.** Сверка с отзывом ревьюера («хендлеры ходят в хранилище напрямую»).
- **Что изменили.** Порты и адаптеры внутри модулей (ADR-001, ADR-003). Правило «API не импортирует адаптеры» проверяет import-linter. Работу проверки доказали: временный импорт репозитория в `api.py` уронил контракт.

### 2026-11-12 · Запасная ветка, которая уронила бы поиск
- **Что произошло.** В расчёте сходства ассистент добавил запасной вариант «если вектор не пришёл — пустой список». Из-за `zip(..., strict=True)` пустой список дал бы `ValueError`, и ответ вместо результата упал бы с 500.
- **Как поймали.** Разбирая предупреждение mypy о возврате `Any` из этой функции, заметили, что ветка не только лишняя (вектор всегда запрошен), но и опасная.
- **Что изменили.** Ветку убрали: вектор читается из явно запрошенного `with_vectors=[DENSE_VECTOR]`, тип результата задан явно.

### 2026-11-12 · Проверка ключа в сигнале Celery, которая не срабатывала
- **Что произошло.** Ассистент проверял `GEMINI_API_KEY` в обработчике сигнала `worker_init`, чтобы worker без ключа не стартовал. Unit-тест вызывал функцию напрямую и был зелёным, а настоящий worker в Docker стартовал без ключа: Celery перехватывает исключения обработчиков сигналов.
- **Как поймали.** Запустили worker в compose без ключа и сверили его статус и логи с ожидаемым. Тест проверял функцию, а не поведение worker-а.
- **Что изменили.** Проверка выполняется при импорте модуля, который загружает `celery -A chartroom.worker`. Поведение подтверждено запуском контейнера без ключа.

### 2026-11-11 · Ветки парсера PDF без тестов
- **Что произошло.** Ассистент написал разделение двух абзацев подряд без заголовка и пропуск строк из пробелов в парсере PDF, но тестов на эти случаи не было: код мог сломаться незаметно.
- **Как поймали.** Порог покрытия с ветвлениями показал две непокрытые ветки.
- **Что изменили.** Сначала проверили на PyMuPDF, что такие случаи бывают на самом деле (ветки нужные, а не мёртвые), затем добавили тест.

### 2026-11-11 · Недостижимая ветка в маппинге ошибок
- **Что произошло.** В обработчике доменных ошибок был запасной статус 400 для ошибок вне категорий. Таких ошибок нет, ветка не исполнялась ни в одном тесте.
- **Как поймали.** Пересмотр кода на мёртвые ветки.
- **Что изменили.** `DomainError → 400` стоит последней строкой таблицы маппинга, отдельной ветки «по умолчанию» нет, случай покрыт тестом. Порог покрытия 95% с учётом ветвлений.
